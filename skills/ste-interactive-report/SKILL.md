# ste-interactive-report · 规范风格 + 分步引导的 HTML 报告

## 什么时候用

- 用户要**研究报告**：单票、行业、竞品、审计、复盘、尽调备忘；
- 报告里**数字密、口径多**，读者需要能一路追到数据源；
- 用户点名「ASD-STE100 / STE / 规范风格 / 短句 / 别写虚的」；
- 用户要「**能一步步看的**」「交互式」「别一屏全是字」。

不适用：宣传页（用 `neo-brutalist-page`）、后台管理台（用 `admin-console-ui-design`）、需要真实后端交互的产品页。纯打印 PDF 可以套本技能，但要额外压掉交互层。

## 两根支柱

| 支柱 | 解决什么 | 硬约束 |
| --- | --- | --- |
| **STE 写作** | 读者不需要重读第二遍 | 一句一个信息；主动语态；固定术语；数字带口径；风险分级 |
| **分步引导** | 读者不需要一次吞下全部 | 七步固定顺序；每步只回答一个问题；全部交互有默认态 |

写和做是同一件事：**先说结论，再给证据，最后给验证点**。不要倒过来。

## 一、中文 STE 落地规则（逐条可检）

ASD-STE100 是英文写作规范，中文按下面的方式落地。八条，写完逐条过。

1. **一句一个信息**。描述句 ≤ 25 字，操作句 ≤ 20 字。出现"并且／同时／尽管"就拆句。
2. **主动语态 + 一般时态**。「分析师上调了目标价」不写「目标价被上调了」。不用「将会／可能将会」这类叠词。
3. **固定术语，一词一义**。开头列**术语表**（术语／含义／本文用法）。同一概念全文只用一个词：并购／收购不同时用；营收／收入选一个。
4. **数字三件套：数值 + 单位 + 口径**。`$840.70（10/30 收盘）`、`+83.2%（FY26 同比）`。禁止裸数字。
5. **不用比喻、不夸张**。「卖铲子的卖铲人」「点火」「史诗级」全部删掉。形容词只在能换成数字时才留。
6. **风险分级用信号词**，并且每个词含义固定：
   - **警告** = 会导致资金损失或结论反转；
   - **小心** = 影响判断，需要读者自己核对；
   - **注意** = 口径、前提、数据局限。
7. **列表优先于长段**。三条以上并列信息一律列表或表格。
8. **结论可被反驳**。每条结论后面跟一个可观测的验证点（日期、事件、指标）。

> 自检口诀：随便抽三句朗读，若任何一句需要读第二遍，重写。

## 二、首屏 + 七步结构（照抄顺序，别改）

| 步 | 回答的问题 | 必备件 |
| --- | --- | --- |
| 首屏 | 一句话能否判定 | 结论句（可反驳，不写口号）+ 3~4 个关键数字条 + 两个入口按钮 |
| 01 结论 | 现在是什么状态 | 4 张事实卡 + 三句话（每句一条独立信息，且不与首屏重复） |
| 02 事件 | 最近发生了什么 | 时间线，7±2 条，每条含日期、事实、当日股价 |
| 03 财务 | 生意在变好还是变坏 | 分季度表 + 分段切换（季度／年度）+ 供给或产能事实 |
| 04 价格 | 股价走到了哪里 | 长周期图 + 近 120 日图 + 关键位置表 |
| 05 估值 | 贵还是便宜 | 交互滑块（EPS × 倍数）+ 多口径对照表 |
| 06 情景 | 接下来有哪些分支 | 4 张情景卡，概率合计 100%，给加权期望 |
| 07 观察 | 我该盯什么 | 可勾选清单，每项带日期或触发条件 |

**步数不是装饰**：导航条、编号、正文左边缘必须**对齐**（见第六节）。折叠时被隐藏的步骤，其 chip 必须变灰且仍可点回，否则编号会跳空。

## 三、交互组件配方

七种，够用。每个组件都要有默认态（不操作时也读得通）。

**1. 步进条**（必须）
顶部 sticky，等宽 chip + 细进度线。点击跳转、滚动高亮（IntersectionObserver）、左右方向键翻页。`scroll-margin-top` 必须 ≥ 顶栏高 + 8px，否则跳转后标题被顶栏压住。

**2. 事件折叠**（必须）
`<details>` 或自绘 accordion。收起时只显示「日期 + 一句事实 + 股价变动」，展开给 2–3 句细节。
坑：折叠面板里不要放表格，展开时高度跳动会很丑。

**3. 分段切换**（可选）
季度／年度、绝对值／百分比这类二选一，用两个按钮 + 两个预渲染的表格（不要用 JS 拼字符串）。

**4. 估值滑块**（强烈建议）
两个 range：预期 EPS、目标倍数。实时输出隐含价格、相对现价百分比、偏离条。
坑：`toFixed(1)` 在 ±0.05% 时显示 `+0.0%`，看起来像坏了；**必须 `toFixed(2)`**。

**5. 情景卡**（必须）
4 张，点击高亮并展开触发条件。价格区间用「相对现价 ±%」而不是绝对值——读者永远在和现价比较。概率合计 100%，下方给加权期望并**明说是主观权重**。

**6. 核对清单**（必须）
checkbox + 进度计数 + localStorage 记忆。每项写清「看什么数字、什么算通过」。

**7. 图表悬停**（建议）
长周期图静态带标注；近 120 日图加十字线 + 当日 OHLC 浮层。SVG 手绘即可，零依赖。

## 四、硬性 token（照抄）

```css
:root{
  --paper:#fbfaf7; --paper2:#f3f1ec; --ink:#16181c; --ink2:#4a4f57; --ink3:#7c828b;
  --line:#e2ded6; --line2:#d3cec4;
  --up:#b23a2f; --down:#1b6b52;   /* 中文报告习惯：红涨绿跌 */
  --accent:#8a6a2f;               /* 全页唯一的第二强调色（金棕） */
  --mono:"SFMono-Regular",Consolas,"Liberation Mono",Menlo,monospace;
  --sans:"Inter","Helvetica Neue",-apple-system,"PingFang SC","Microsoft YaHei",sans-serif;
}
```

- **数字一律等宽 + 右对齐**：`font-variant-numeric:tabular-nums`，`td.num{text-align:right}`。
- 正文 15.5–16px，行高 1.75；表格 12.5–13.5px；小标 mono 11px + `letter-spacing:.16em`。
- 上涨用红、下跌用绿，**并且永远同时写 +/− 号**，避免美式绿涨红跌误读。
- 一个页面只有一个强调色。强调用左侧 2px 竖条或背景微亮，不用彩色大色块。

## 五、数据口径纪律（最容易翻车的地方）

| 坑 | 做法 |
| --- | --- |
| GAAP 与 non-GAAP 混用 | 主表用 non-GAAP 并在表注说明；GAAP 差异单独一行（一次性非现金损失要标出） |
| 公司指引 vs 卖方一致预期 | 两者分开列，标注来源；不一致时**明确指出口径差异**，不要选好看的那个 |
| 财季标签 | `FQ4 FY26（2026-06-27）` 这种写明截止日的写法，避免财年错位 |
| 未取得的字段 | 填 `—` 并在表注解释，**不要估算后混进表里** |
| 年中数据 | 说明区间起点，别写"一年涨 292%"却说不出从哪天算起 |
| 第三方报道的交易细节 | 一律标注「媒体援引匿名消息，公司未确认」 |

**每个数字都要能追溯**：文末列数据源（一手优先：SEC 原始公告 > 交易所行情 > 财经媒体 > 二手转述）。

## 六、版式对齐纪律（踩过的坑，逐条照做）

1. **一个左边缘**。步骤编号做成标题上方的独立小标（`03 / 07`），不要和 `h2` 并排缩进——并排会把标题推到右二，正文留在左一，一眼就歪。
2. **折叠模式不许跳号**。隐藏中间几步时，被隐藏步骤的 chip 要变灰；点灰 chip **先退出折叠再跳转**，否则点了没反应。
3. **SVG 坐标轴取整**。`niceStep` 算刻度（1/2/2.5/5×10ⁿ），不要让轴上出现 `−$56`、`$1,176` 这种数字。
4. **面积图从 0 起**。折线图可以从数据下沿起，面积图不行——填充高度会被读成数值。
5. **标注带白色光晕**：`paint-order:stroke; stroke:#fff; stroke-width:3`，否则压在网格线或折线上看不清。
6. **标注避让**：峰值标上方、低点标下方、最新价标右侧留白处。图例里已经有的信息不要在图内重复标注。
7. **窄屏表格横滑**：`@media(max-width:820px){ .tscroll table{min-width:620px} }`。只加 `overflow-x:auto` 不够——`width:100%` 会把 7 列表挤成多行，比横滑难读得多。
8. **正文与图表共享同一条中线**：图和表都套在同一个 `max-width` 容器内，别让图比表宽。

## 七、交付前验收清单

- [ ] 抽三句朗读，每句一遍读懂
- [ ] 每条结论后面有验证点
- [ ] 所有数字带单位与口径
- [ ] 表格里没有混口径，`—` 有解释
- [ ] 导航 7 步与正文编号一一对应
- [ ] 折叠模式：chip 变灰、点灰 chip 自动展开
- [ ] 每个交互控件都能在不操作时读通
- [ ] 桌面 + 420px 窄屏都无横向溢出
- [ ] 正文结论与数字必须写死在 HTML 里（图表、滑块、折叠等交互层可以依赖 JS）
- [ ] 文末有数据源、口径说明、免责声明

## 八、自检脚本

```bash
bun run skills/ste-interactive-report/scripts/selfcheck.ts path/to/report.html 8820
```

做四件事：起本地服务 → 抓 JS 报错（监听在 load 之后注入，只覆盖交互期间） → 跑断言（无溢出／步数对齐／chip 跳转／折叠模式／滑块联动／情景卡／清单计数／窄屏）→ 分段截图到 `shots/`。退出码 0 为通过。
断言按元素存在性跳过，所以同一脚本也能验别的报告页。
